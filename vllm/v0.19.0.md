## 本版导读

0.19.0 是 v1 引擎全面接管后的第一个"打磨调度与硬件"的版本，三条主线收束在这一版：**零气泡异步调度与投机解码汇合**（`#32951` 让 prefill/decode 的气泡被投机草稿填满，是把 MTP/Eagle 的吞吐真正吃满的关键一步）、**CPU KV Cache 卸载走向通用**（`#37160` 一个简洁通用的 CPU offload 落地，`#37874` 紧接着把它重构为可插拔 CachePolicy，为显存换吞吐铺路）、**B300/GB300（SM 10.3）首发调优**（all-reduce 通信、融合、kernel 都为新一代 Blackwell 服务器做了适配）。如果你正在做长上下文 + 投机解码的部署，这版的"零气泡 + CPU KV 卸载"组合是降本最实在的两组改动。同时 ViT 全图 CUDA Graph（`#35963`）让多模态视觉编码器的开销显著下降，Gemma 4 全家桶（`#38826`）落地。

## 头条亮点

1. **零气泡异步调度 + 投机解码（#32951）**：`[Async][Spec Decoding] Zero-bubble async scheduling + spec decoding`。把异步调度（async scheduling）与投机解码打通，在 prefill/decode 的空隙里塞入投机草稿验证，让"气泡"被有效计算填满。这是把 MTP/Eagle 等高频 proposer 的吞吐从"理论加速"变成"实测吃满"的关键改动——投机解码不再只为降延迟，也开始为填气泡服务。配套有 `[Model Runner V2] Consider spec decoding in warmup`（#37812）、rejection sampler 的 greedy/logprobs 支持（#37237/#37238）、draft logits 用 fp32（#37526）、cudagraph replay 下 draft logits 修复（#37639）等一系列稳健性补强。

2. **通用 CPU KV Cache 卸载（#37160 + #37874）**：`[Feat][v1] Simple yet General CPU KV Cache Offloading`（#37160）落地一套简洁通用的 CPU KV 卸载机制；`#37874` 紧接着重构为可插拔 `CachePolicy`、移除 Backend 抽象、整理进 `cpu/` 包。对长上下文/大 batch 场景，用 CPU 内存换 GPU 显存是显存不够时的标准解法，这版把它从"实验性"提到"通用可插拔"。叠加 `kv_offload+HMA` 系列（#36642/#37405/#37853 支持多 KV group、hybrid 模型 register_kv_caches）、Mooncake connector 异构 TP（#36869），P/D 分离 + KV 卸载的生态进一步完整。

3. **B300/GB300（SM 10.3）首发调优（#37755 + #37756）**：`[Perf] Add SM 10.3 (B300/GB300) all-reduce communicator tuning`（#37756）为新一代 Blackwell 服务器调优 all-reduce 通信器；`#37755` 默认开启 all-reduce 融合。这是 vLLM 对最新一代 NVL 服务器（B300/GB300）的首批适配，直接关系到大规模 TP 部署的通信开销。

4. **ViT 全图 CUDA Graph（#35963）**：`[Feature] ViT Full CUDA Graph`。视觉编码器整体进入 CUDA Graph，消除 per-op 的 kernel launch 开销——多模态模型在视觉前处理阶段的延迟与抖动显著下降。配合 `Optimize glm4.xv VIT`（#37779）、编码器 budget 控制（Gemma4 编码器预算见后续版本），多模态视觉路径在本版系统性提速。

## 新特性 [Feature]

- **Gemma 4 全家桶（#38826）**：`feat(models): implement Google Gemma 4 architecture support (MoE, Multimodal, Reasoning, Tool-Use)`。Gemma 4 一次性落地 MoE 架构、多模态、推理（reasoning）、工具调用四大能力，是本版体量最大的新模型。
- **EPLB 支持 Model Runner V2（#37488）**：`[Feature] EPLB Support for GPU Model Runner v2`，专家负载均衡（Expert Load Balancing）接入新引擎。配套 EPLB transfer 逻辑清理（#34520）、简化 rearrange 只返回一个 map（#36267）、移除慢 EPLB 下的主等待（#36271）。
- **per-draft-model MoE 后端（#37880）**：`Support per-draft-model MoE backend via --speculative-config`，投机解码的草稿模型可单独指定 MoE 后端——drafter 与 target 用不同后端成为可能。
- **限制 thinking tokens 硬上限（#20859）**：`limit thinking tokens (hard limit)`，给推理类模型的"思考预算"加硬封顶，防失控。
- **Cohere Embed v2 API（#37074）**：`[Feature][Frontend] add support for Cohere Embed v2 API`。
- **单次推理多种 embedding 类型（#35829）**：`Support for multiple embedding types in a single inference call`。
- **Qwen3-ForcedAligner（#35367）**：通过 token 分类 pooling 支持 Qwen3 的 ForcedAligner。
- **Nemotron HPuzzle + HMTP（#37803）**：`Enable NemotronHPuzzle + NemotronHMTP`，Nemotron 系的 MTP 投机解码模型落地。
- **在线 MXFP8 量化（#35448）**：`Support online MXFP8 quantization for MoE and dense models`，MoE 与稠密模型都支持在线 MXFP8 量化。
- **`-sc` 短选项（#38380）**：为 `--speculative-config` 增加短旗标，方便命令行启用投机解码。

## 投机解码 & MTP 相关

本版投机解码的核心是"与异步调度/新引擎深度融合"，而非新增 proposer 模型：

- **零气泡异步调度 + spec decoding（#32951）**：见头条亮点 1。
- **per-draft-model MoE 后端（#37880）**：草稿模型独立 MoE 后端。
- **MRv2 warmup 考虑 spec decoding（#37812）**：预热阶段纳入投机解码。
- **rejection sampler greedy（#37238）+ logprobs（#37237）支持**：补齐投机解码采样路径。
- **draft logits 用 fp32（#37526）+ cudagraph replay 下 draft logits 修复（#37639）**：提升投机解码数值稳定性。
- **draft attention metadata 修复（#37364）+ rebuild before eagle decode（#38311）**。
- **多模态 embeddings 与 spec decode（#36097/#37932）**：MRv2 支持多模态投机解码。
- **Nemotron HMTP（#37803）+ Pixtral Eagle3（#37182）**：新模型 + 新 proposer。
- **Eagle3 norm_before_fc 传播修复（#38111）+ drafter quant_config 传递（#37280）**。
- **强制指定 acceptance rate（#38045）**：调试/评测时可强制接受率。
- **hybrid 模型异步 spec decoding 修复（#38556）**。

## 核心改动 [Core]

- **按 full ISL 调度请求（#37307）**：`add option to schedule requests based on full ISL`，调度器可基于完整输入序列长度调度——与长上下文 + CPU KV 卸载场景相关。
- **KV Connector 错误处理移除 num_cached_tokens 依赖（#38096）**。
- **kv_offload+HMA 系列（#36642/#37405/#37853）**：多 KV group、拆分 offloading_connector、hybrid 模型 register_kv_caches——CPU KV 卸载对 hybrid 架构（如 MLA+普通注意力混合）的支撑。
- **Mooncake connector 单测 + 异构 TP（#36946/#36869）**：P/D 分离的 Mooncake 连接器成熟化。

## 升级建议

- **如果你用 MTP/Eagle 投机解码**：这版是强烈建议升级的版本。零气泡调度（#32951）直接提升吞吐，且配套修了一堆 MRv2 下投机解码的稳定性问题（draft logits、attention metadata、cudagraph replay）。升级前注意把 `--speculative-config` 的草稿模型 MoE 后端配置（#37880）纳入回归测试。
- **如果你跑长上下文 / 显存吃紧**：开启 CPU KV 卸载（#37160），注意它在本版已重构为可插拔 CachePolicy（#37874），旧的 Backend 抽象被移除——若你之前用了实验性 offload API，需按新接口调整。
- **如果你用 Blackwell B300/GB300**：这版是首批适配版本，all-reduce 调优（#37756）与默认融合（#37755）建议直接吃下。
- **如果你用多模态模型**：ViT 全图 CUDA Graph（#35963）降延迟，但要注意视觉编码器的 cudagraph 内存池配置，大分辨率输入需回归。
- **量化路径**：PTPC FP8 被移除（#32700），仍在用该量化的需迁移到 NVFP4/MXFP4/MXFP8。
- **DBO（microbatch 优化）**：本版泛化到通用模型（#37926），若你之前因模型不兼容没开 DBO，可重新评估。
