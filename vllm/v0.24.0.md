## 头条亮点

1. **投机解码全面成熟：MTP / EAGLE / DFlash / Dynamic SD 多线并进**。本版投机解码是最大的方向性进展，尤其利好"用 MTP 部署 glm-5.2"的场景：`[Spec Decode] Add Gemma4 MTP speculative decoding support`（#41745，新增 `gemma4_mtp.py` 603 行 + `v1/spec_decode/gemma4.py` 335 行）把 MTP 作为 proposer 原生接入 v1；`[SpecDecoding] extend mtp support for mimo 2.5`（#41905）扩展 MiMo-V2.5 的 MTP；`[V1][Spec Decode] Add Dynamic SD`（#32374）引入动态投机解码（按 acceptance 动态调整草稿长度）；`[Spec Decode] Add Qwen3 architecture support for EAGLE3`（#43132，+453 行 `qwen3_eagle3.py`）让 EAGLE3 支持 Qwen3 架构；`[MRV2][Spec Decode] DFlash`（#44586）把 DFlash 投机解码接入 Model Runner V2；`[SpecDecode] Reduce TP communication for large-vocab draft models`（#39419）专门优化大词表草稿模型的 TP 通信（Qwen3 / DeepSeek-EAGLE3 直接受益）。叠加 `[Reasoning] Support for speculative decoding with thinking budget`（#34668，+528 行 `thinking_budget_state.py`）——**带思考预算的推理也能叠加投机解码**，这对 glm-5.2 这类带 thinking 的模型部署是直接利好。

2. **MLA 注意力后端结构性重构 + GLM-5 适配**。`[Attention] Abstract the MLA prefill backends and eliminate cuDNN`（#32623，+1629 行）把 MLA prefill 后端抽象为可注册的 registry（flash_attn / flashinfer / trtllm_ragged），彻底移除 cuDNN 依赖，并支持 out-of-tree 注册自定义后端。在此基础上 `[MLA Attention Backend] Add TOKENSPEED_MLA backend`（#41778）为 Blackwell 平台 DSR1/Kimi K25 新增独立后端；`[Kernel] Support GLM-5 dimensions for TRT-LLM ragged MLA prefill`（#43525）让 TRT-LLM ragged MLA prefill 支持 GLM-5 的维度；`[Kernel] GLM5 Router GEMM`（#46385）为 GLM-5 的 MoE 路由新增专用 GEMM kernel；`[Frontend] Add Streaming Parser Engine and new GLM4.7/GLM5.1/GLM5.2 Parser`（#45915）新增 GLM5.1/GLM5.2 的流式 tool parser。**从 MLA prefill kernel 到 MoE router GEMM 到 tool parser，GLM-5 全栈得到适配**。

3. **P/D 分离 + KV 传输生态大幅成熟**。`[P/D] Prefill compute optimizations with bi-directional KV cache transfers between P and D nodes`（#32553，+1570 行）支持 P/D 节点间双向 KV 传输，prefill 计算与 KV 传输重叠；`[KV Transfer] Add MooncakeStoreConnector`（#40900，+2600 行）用 Mooncake 分布式 store 做 KV offload；`[KV Connector][Mooncake] Pipeline-parallel support for PD-disaggregated serving`（#44528，+680 行）让 Mooncake 支持 pipeline-parallel 的 P/D 分离；`[WideEP] Integrate DeepEP v2`（#41183，+542 行测试）集成 DeepEP v2 用于 WideEP；NIXL connector 升级到 1.x（#42364）并新增 per-region KV transfer 分类（#44583）。叠加 `[KV Offload] Enable HMA models for Tiering Offloading`（#44287）、`[Attention] Re-enable cross-layer KV cache layout for MLA`（#45111）——**KV cache offload / HMA / cross-layer layout / Mooncake / DeepEP v2 形成完整的 P/D 分离栈**。

4. **NVFP4 / MXFP4 量化全链路深化**。`[Quantization] Add ModelOpt NVFP4 W4A16`（#41769，4-bit 权重 + fp16/bf16 激活）、`Add nvfp4 kv cache support`（#40177，KV cache 用 NVFP4 存储）、`[Kernel][Performance] Add FlashInfer cutedsl NVFP4 GEMM backend`（#42235）、`[Kernel] Add FlashInferCutedslMxfp8LinearKernel`（#46393，cute-dsl mm_mxfp8）、`[Feature] TurboQuant: support hybrid models and uniform quantization`（#39931）、`[Kernel][MoE] Support GELU on TRT-LLM NvFP4 fused MoE for Gemma4`（#41050）。**NVFP4/MXFP4 从权重到 KV cache 到 MoE fused kernel 到 GEMM backend 形成闭环，对显存受限场景意义重大**。
