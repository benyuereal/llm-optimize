# vLLM v0.21.0 重大更新（相对 v0.20.0）

> 本段约 395 个 commit，以下为重大更新摘要（已过滤 Bugfix/CI/Docs/Refactor/Test/Build/ROCm/XPU/CPU 等日常维护）。
> 统计：[Bugfix] 74、[CI] 34、[ROCm] 32、[Perf] 11、[Model] 10、[Attention] 6、[Core] 5、[Feature/Feat] 10、[MM] 3、[Kernel] 3、[MoE] 2、[Quantization] 2、[LoRA] 1、[EPLB] 1、[SpecDecoding] 1 等。筛选后得到约 67 条重大更新。

## 头条亮点

1. **Gemma4 MTP 投机解码落地（#41745）**：新增 `vllm/model_executor/models/gemma4_mtp.py`（603 行）与 `vllm/v1/spec_decode/gemma4.py`（335 行），把 MTP（Multi-Token Prediction）作为 proposer 接入 v1 投机解码框架，并扩展 `speculative.py` 配置。这是本版对"用 MTP 部署"最直接的利好——MTP 不再只是 DeepSeek/Glm 系的专属路线，Gemma4 也加入了原生支持。同时 `[SpecDecoding] extend mtp support for mimo 2.5`（#41905）与 MiMo-V2.5 的 MTP 模型（#40967）一起，进一步丰富了 MTP 生态。

2. **TOKENSPEED_MLA 注意力后端（#41778）**：为 Blackwell 平台的 DSR1 / Kimi K25 新增独立 MLA prefill+decode 后端（`tokenspeed_mla.py` 277 行 + prefill 180 行），并配套 attention benchmark 配置。叠加 `[Attention] Abstract the MLA prefill backends and eliminate cuDNN`（#32623，+1629 行重构）——MLA prefill 后端被抽象为可注册的 registry（flash_attn / flashinfer / trtllm_ragged / tokenspeed），彻底移除 cuDNN 依赖。对 DeepSeek 系/MLA 模型的吞吐与可维护性是结构性提升。

3. **P/D 分离 + 双向 KV 传输（#32553）**：新增 `disagg_proxy_multiturn.py`（562 行）与 `test_bidirectional_kv_transfer.py`（915 行），支持 P（prefill）与 D（decode）节点之间**双向** KV cache 传输，prefill 计算可与 KV 传输重叠。配合 `MooncakeStoreConnector`（#40900，+2600 行，Mooncake 分布式 store 做 KV offload）、`MultiConnector SupportsHMA`（#39571）、NIXL connector 升级到 1.x（#42364）与 zero-copy EPLB 传输（#41633），P/D disaggregation 本版显著成熟。

4. **NVFP4 量化全链路打通**：`Add nvfp4 kv cache support`（#40177）让 KV cache 也可用 NVFP4 存储；`ModelOpt NVFP4 W4A16`（#41769）支持 4-bit 权重 + fp16/bf16 激活；`NVFP4 all-gather GEMM fusion for AsyncTP`（#41882）在异步 TP 下融合 all-gather 与 GEMM；外加 Triton NVFP4 dequant/QDQ emulation kernel（#40033）、Blackwell per-token fp8 group quant（#41326）。NVFP4 从权重到 KV cache 到 TP 融合形成闭环，对显存受限场景意义重大。

## 新特性 [Feature]

- **TurboQuant 支持混合模型与统一量化（#39931）**：扩展 `turboquant/config.py`，让 TurboQuant 可作用于混合架构模型，并支持统一量化配置。
- **Triton kernel JIT 编译监控（#40137）**：为推理过程加入 Triton kernel 的 JIT 编译监控，便于发现编译热点与卡顿。
- **IndexCache 支持 DSA 模型（#37735）**：DeepSeek Attention（DSA / MLA）模型也能用 IndexCache，更新 `layers/mla.py` 与 `deepseek_v2.py`，配套文档 `index_cache.md`。
- **显式权重迁移 API（#39212）**：新增 `/start_weight_update` 与 `/finish_weight_update` 两个 API，用于运行时权重传输（weight transfer），为在线权重热更新提供标准入口。
- **Cohere reasoning + tool parser（#40422）**：新增 Cohere Command 的 reasoning parser（546 行）与 tool parser（127 行），让 Cohere 模型支持推理输出与工具调用解析。
- **EagleMistralForCausalLM（#41024）**：新增基于 Eagle 的 Mistral 投机解码 drafter 模型实现。
- **CPU Gated DeltaNet Attention（#41025）**：在 CPU 上启用门控 DeltaNet 注意力，支持 Qwen 3.5 / 3.6。
- **CPU fp8 attention（AMX/AVX-512，#39445）**：CPU 后端支持 fp8 注意力计算。
- **dnnl 构建 AVX2 W8A8 Int8（#41318）**：通过 oneDNN 构建 AVX2 平台 W8A8 Int8 支持。
- **struct tag 严格工具调用 + 推理（#40894）**：升级 xgrammar 到 0.2.0，用 structural tags 实现严格工具调用与推理，新增 `structural_tag_registry.py`（330 行）及 DeepSeek-V4 / Qwen3-Coder tool parser 测试。
- **LFM2/2.5 Tool Parser（#39243）**：新增 LFM2/2.5 工具调用解析器（343 行）。
- **多模态模型投机解码放行（#41752）**：`[Spec Decode] Allow multimodal models with a warning`，多模态模型也可启用投机解码（带告警）。

## 性能优化 [Perf]

- **消除 attention 实现中的 GPU<->CPU 同步（#41434，3/n）**：系列改动（含 pooling 代码 #41433）系统性消除 attention / pooling 路径里的 host-device 同步点，直接降低每步延迟。
- **DeepSeek-V4 head_compute_mix kernel（#41255）**：集成 Tile Kernels 的 `head_compute_mix_kernel`，针对 DeepSeek-V4 的注意力头计算优化。
- **AllPool.forward 切片优化（#41163）**：先切片再计算，方法级 benchmark 快 51%。
- **FlashInfer top-k/top-p 采样器默认开启（#40376）**：用 FlashInfer 融合采样替代原实现，提升采样吞吐。
- **FP8 FlashInfer Attention for ViT（#38065）**：视觉编码器注意力走 FP8 FlashInfer 路径，降显存提速度。
- **W8W8 group quant 用 2D-grid 消除 divmod（#42153）**：重构 group quant kernel 的 grid 维度，去掉 divmod 开销。
- **safetensors checkpoint 预取可配置（#41499）**：把 checkpoint 预取设置暴露为可配置项，便于按场景调优加载。
- **投机解码 prepare_next_step 去除每步 numpy 分配（#41043）**：消除投机解码每步的 numpy 内存分配，降低开销——对 MTP/Eagle 等高频 proposer 直接受益。
- **forward_native sampler kernel 预热（#41375）**：减少首步采样延迟。
- **TRTLLM MoE routing 方法更新（#39141）**：扩展 TRTLLM 支持的 MoE routing 方法集。
- **embedding float 响应序列化走 numpy zero-copy（#41681）**：embedding 输出序列化用 zero-copy 路径，减少拷贝。
- **批量 KV cache swap 用 CU_MEMCPY_SRC_ACCESS_ORDER_ANY（#39306）**：CPU offload 的批量 KV 交换用更宽松的拷贝顺序，提升并发。
- **DSv4 sparse FP8 compressor kernel 优化（#44161）**：优化 DeepSeek-V4 稀疏 FP8 压缩 kernel。

## 核心改动 [Core]

- **MoE 路由 replay 改为 device cache + 异步 D2H pipeline（#39917）**：用设备侧缓存 + 异步 D2H 传输替代原 routing replay 机制（`routed_experts_capturer.py` 改动 1058 行），新增 `routed_experts_replay` 配置与文档。显著降低 MoE 专家路由捕获的开销。
- **UniProcExecutor 去掉额外线程（#40891）**：单进程执行器不再多开线程，减少调度开销。
- **`scheduler_reserve_full_isl` 选项处理简化（#41064）**：简化该调度选项的处理逻辑。
- **`num_gpu_blocks_override` 纳入 max_model_len 校验（#41069）**：避免显存块覆盖与最大模型长度不一致导致的隐患——与长上下文场景相关。
- **StepPool.forward chunked prefill 冗余 None 修复（#41049）**：清理 chunked prefill 路径的冗余追加。
- **MLA prefill 后端抽象 + 移除 cuDNN（#32623）**：见头条亮点 2，结构性的注意力后端重构。
- **persistent MLA for sparse MLA backend（#41990）**：为 sparse MLA 后端启用 persistent 实现。
- **OOT MLA prefill 后端注册机制（#43325）**：支持 out-of-tree 注册自定义 MLA prefill 后端。
- **FlexAttention / FlashAttention 改 num-blocks-first 布局（#42095）**：统一 KV layout 为 blocks-first。
- **MoERunnerInterface 成为 PluggableLayer（#35178）**：MoE runner 支持以插件层方式扩展，便于 OOT 自定义 MoE。

## Kernel / Attention / Quantization / MoE / MM / LoRA

### Kernel / Attention
- **FA3→FA4 升级移入 get_flash_attn_version()（#40815）**：FlashAttention 3→4 的版本升级逻辑统一到版本探测函数，便于平滑切换到 FA4。
- **MLA prefill backend 所有权归层（#41744）**：注意力层接管 MLA prefill backend 的所有权。
- **TurboQuant 共享 dequant buffer，消除 float16_copy（#40941）**：去量化缓冲复用，去掉一次 float16 拷贝。
- **Helion config 解析延迟优化（#40850）**：优化 Helion kernel 的配置解析耗时。
- **DCP A2A 打包 output 与 LSE（#41160）**：在 DCP all-to-all 中合并输出与 LSE 打包，减少通信次数。
- **Marlin MoE 默认架构含 SM 12.x（#40923）**：Marlin MoE kernel 默认编译覆盖 Blackwell SM 12.x。
- **TritonW4A16 作为非 Marlin 对齐形状的 CUDA fallback（#43731）**：形状不满足 Marlin 对齐时回退到 Triton W4A16 kernel。
- **fuse_minimax_qk_norm 手工融合（#43410）**：把 qk_norm 融合改为手工融合实现。
- **CPU 标准 KV layout blocks-first（#44393）**、**AMD 标准 KV layout blocks-first（#43660）**：统一各硬件 KV 布局。
- **Power VSX Attention Backend（#40451）**：PowerPC 平台新增 VSX 注意力后端并修复 L2 cache crash；后续启用 SHM communicator（#43754）。

- **NVFP4 all-gather GEMM fusion for AsyncTP（#41882）**：异步 TP 下融合 all-gather 与 GEMM。
- **Triton NVFP4 dequant / QDQ emulation（#40033）**：Hopper / AMD Instinct 上的 NVFP4 反量化与 QDQ 仿真 kernel。

- **Humming mxfp4 MoE backend（#41083）**：新增 Humming 的 mxfp4 MoE 后端。
- **CUTLASS scaled mm 支持非兼容尺寸（#41868）**：放宽 cutlass scaled mm 的尺寸限制。
- **DSV4 Indexer Q 量化 kernel 改进（#41428）**：改进 fused Indexer Q 量化 kernel。
- **FlashInfer FP8 async TP fusion（#39505）**：FlashInfer FP8 下异步 TP 融合并保留 allreduce 融合顺序。

- **自动选择已注册视频加载器（#44126）**：VLM 自动选用注册的视频 loader。

## 投机解码 & MTP 相关

本版对投机解码/MTP 是重点版本，多条改动直接利好"用 MTP 部署 glm-5.2"这类场景：

- **Gemma4 MTP 投机解码（#41745）**：新增 `gemma4_mtp.py`（603 行）+ `v1/spec_decode/gemma4.py`（335 行），MTP 作为 proposer 接入 v1 投机解码；扩展 `config/speculative.py`。**MTP proposer 框架进一步通用化。**
- **MiMo-V2.5 MTP（#40967）+ mimo 2.5 MTP 扩展（#41905）**：MiMo-V2.5 的 `mimo_v2_mtp.py`（373 行）落地，并扩展对 mimo 2.5 的 MTP 支持。
- **DSV4 base + MTP 头（#41006）**：DeepSeek-V4 基座与其 MTP 头一并支持。
- **EagleMistralForCausalLM（#41024）**：新增 Eagle drafter 模型。
- **Cohere Eagle（#42078）**：Cohere MoE 配套 Eagle 投机解码 drafter。
- **drafter 可独立选择注意力后端（#39930）**：`[Attention][Spec Decode]` 允许 drafter 用与 target 不同的注意力后端——可针对小模型 drafter 选更轻量后端。
- **投机解码 + thinking budget（#34668）**：新增 `thinking_budget_state.py`（528 行），把推理 thinking budget 与投机解码结合，rejection sampler / sampler 联动——对带思考预算的模型 + 投机解码组合很重要。
- **投机解码 prepare_next_step 去 numpy 分配（#41043）**：降低每步开销，MTP/Eagle 高频 proposer 直接受益。
- **多模态模型可启用投机解码（#41752）**：放行多模态 + spec decode（带告警）。
