# vLLM v0.22.0 重大更新（相对 v0.21.0）

> 本版约 474 个 commit，以下为重大更新摘要（已过滤 Bugfix/CI/Docs/Refactor 等日常维护）。仅依据 commit 标题与必要时的 `git show --stat` 改动范围判断，未逐行审阅 diff。

## 头条亮点

1. **DeepSeek V4 全栈落地**：本版最大主线。新增 DSV4 基础模型支持（含其 MTP，`deepseek_v4.py` / `deepseek_v4_mtp.py`），围绕 Sparse MLA、MHC（multi-head latent）kernel、FP8 稀疏 compressor、Tile Kernels `head_compute_mix_kernel`、TRTLLM gen attention kernel 做了大量性能与重构工作；KV Connector / CPU offload / 前缀缓存（含 sliding-window KV 选择性保留）全面适配 DSV4。这是你用 MTP 部署 GLM-5.2 时最值得对照参考的工程范式。

2. **投机解码与 MTP 持续扩展**：新增 Gemma4 MTP 投机解码（`gemma4_mtp.py` + `v1/spec_decode/gemma4.py`，1121 行新增）、EagleMistral 模型、Cohere Eagle、MiMo 2.5 的 MTP 扩展；支持「带 thinking budget 的投机解码」（reasoning + spec decode 联动，`thinking_budget_state.py` 528 行新增）；允许 drafter 独立选择 attention backend；多模态模型在告警下也可用投机解码。**直接利好 MTP 部署链路。**

3. **KV Cache 二级卸载（Tiered Offloading）体系化**：引入 objectstore 作为二级 KV cache 卸载层，新增 `SecondaryTierManager`、per-request 卸载策略（`on_new_request` 生命周期钩子）、`on_schedule_end()` 步级生命周期分离；HMA 模型默认启用 tiering offload；Mooncake/Nixl connector 大量健壮性与可观测性增强。PD 分离架构进一步成熟。

4. **量化与 MoE 内核全面铺开**：TurboQuant 支持混合模型 + 均匀量化；新增 ModelOpt NVFP4 W4A16、compressed-tensors WNA8O8Int linears、 humming mxfp4 MoE backend；MoE 路由从 routing replay 改为 device cache + 异步 D2H pipeline；W4A8/W4A16/NVFP4/MXFP8 多个 MoE 量化路径迁移到 oracle kernel 架构；LoRA 首次支持 Expert Parallel（EP）+ MoE LoRA one-shot Triton kernel。

- **[Perf] Optimize Fp8BlockScaledMMLinearKernel input_scale tensor using new_empty() (#43677)** — 用 new_empty() 优化 input_scale tensor 分配。

## 投机解码 & MTP 相关

> 本版投机解码相关进展集中，且与你用 MTP 部署 GLM-5.2 的场景高度相关。

- **[Spec Decode] Add Gemma4 MTP speculative decoding support (#41745)** — 新增 Gemma4 MTP 投机解码（`gemma4_mtp.py` 603 行 + `v1/spec_decode/gemma4.py` 335 行，含 `llm_base_proposer.py` 改造）。是本版最完整的新 MTP 实现范本。

- **[Reasoning] Support for speculative decoding with thinking budget (#34668)** — 带 thinking budget 的推理与投机解码联动（新增 `thinking_budget_state.py` 528 行）。**对带思考链的 MTP 部署是关键能力。**
- **[Attention][Spec Decode] Allow independent drafter attention backend selection (#39930)** — drafter 可用与 target 不同的 attention 后端，便于为 MTP/Eagle 的 draft 模型选更轻量 kernel。
- **[Spec Decode] Allow multimodal models with a warning (#41752)** — 多模态模型在告警下也可用投机解码。
- **[Feature] Add EagleMistralForCausalLM (#41024)** — Eagle 投机解码新增 Mistral 实现。

- **[Model Runner V2] Rebuild attn metadata between draft decode steps (#41162)** / **Skip attention metadata rebuild before draft prefill (#40410)** / **Fix rejection sampling acceptance rate gap vs MRV1 (#40651)** — MRV2 下投机解码的 attn metadata 重建与拒绝采样接受率对齐，MRV2 的投机解码逐步成熟。
