### 本版导读

0.19.0 是 v1 引擎全面接管后的第一个"打磨调度与硬件"的版本，三条主线收束在这一版：**零气泡异步调度与投机解码汇合**（`#32951` 让 prefill/decode 的气泡被投机草稿填满，是把 MTP/Eagle 的吞吐真正吃满的关键一步）、**CPU KV Cache 卸载走向通用**（`#37160` 一个简洁通用的 CPU offload 落地，`#37874` 紧接着把它重构为可插拔 CachePolicy，为显存换吞吐铺路）、**B300/GB300（SM 10.3）首发调优**（all-reduce 通信、融合、kernel 都为新一代 Blackwell 服务器做了适配）。如果你正在做长上下文 + 投机解码的部署，这版的"零气泡 + CPU KV 卸载"组合是降本最实在的两组改动。同时 ViT 全图 CUDA Graph（`#35963`）让多模态视觉编码器的开销显著下降，Gemma 4 全家桶（`#38826`）落地。

### 头条亮点

1. **零气泡异步调度 + 投机解码（#32951）**：`[Async][Spec Decoding] Zero-bubble async scheduling + spec decoding`。把异步调度（async scheduling）与投机解码打通，在 prefill/decode 的空隙里塞入投机草稿验证，让"气泡"被有效计算填满。这是把 MTP/Eagle 等高频 proposer 的吞吐从"理论加速"变成"实测吃满"的关键改动——投机解码不再只为降延迟，也开始为填气泡服务。配套有 `[Model Runner V2] Consider spec decoding in warmup`（#37812）、rejection sampler 的 greedy/logprobs 支持（#37237/#37238）、draft logits 用 fp32（#37526）、cudagraph replay 下 draft logits 修复（#37639）等一系列稳健性补强。

2. **通用 CPU KV Cache 卸载（#37160 + #37874）**：`[Feat][v1] Simple yet General CPU KV Cache Offloading`（#37160）落地一套简洁通用的 CPU KV 卸载机制；`#37874` 紧接着重构为可插拔 `CachePolicy`、移除 Backend 抽象、整理进 `cpu/` 包。对长上下文/大 batch 场景，用 CPU 内存换 GPU 显存是显存不够时的标准解法，这版把它从"实验性"提到"通用可插拔"。叠加 `kv_offload+HMA` 系列（#36642/#37405/#37853 支持多 KV group、hybrid 模型 register_kv_caches）、Mooncake connector 异构 TP（#36869），P/D 分离 + KV 卸载的生态进一步完整。

3. **B300/GB300（SM 10.3）首发调优（#37755 + #37756）**：`[Perf] Add SM 10.3 (B300/GB300) all-reduce communicator tuning`（#37756）为新一代 Blackwell 服务器调优 all-reduce 通信器；`#37755` 默认开启 all-reduce 融合。这是 vLLM 对最新一代 NVL 服务器（B300/GB300）的首批适配，直接关系到大规模 TP 部署的通信开销。

4. **ViT 全图 CUDA Graph（#35963）**：`[Feature] ViT Full CUDA Graph`。视觉编码器整体进入 CUDA Graph，消除 per-op 的 kernel launch 开销——多模态模型在视觉前处理阶段的延迟与抖动显著下降。配合 `Optimize glm4.xv VIT`（#37779）、编码器 budget 控制（Gemma4 编码器预算见后续版本），多模态视觉路径在本版系统性提速。

### 升级建议

- **如果你用 MTP/Eagle 投机解码**：这版是强烈建议升级的版本。零气泡调度（#32951）直接提升吞吐，且配套修了一堆 MRv2 下投机解码的稳定性问题（draft logits、attention metadata、cudagraph replay）。升级前注意把 `--speculative-config` 的草稿模型 MoE 后端配置（#37880）纳入回归测试。
- **如果你跑长上下文 / 显存吃紧**：开启 CPU KV 卸载（#37160），注意它在本版已重构为可插拔 CachePolicy（#37874），旧的 Backend 抽象被移除——若你之前用了实验性 offload API，需按新接口调整。
- **如果你用 Blackwell B300/GB300**：这版是首批适配版本，all-reduce 调优（#37756）与默认融合（#37755）建议直接吃下。
- **如果你用多模态模型**：ViT 全图 CUDA Graph（#35963）降延迟，但要注意视觉编码器的 cudagraph 内存池配置，大分辨率输入需回归。
- **量化路径**：PTPC FP8 被移除（#32700），仍在用该量化的需迁移到 NVFP4/MXFP4/MXFP8。
- **DBO（microbatch 优化）**：本版泛化到通用模型（#37926），若你之前因模型不兼容没开 DBO，可重新评估。

## vLLM v0.21.0 重大更新（相对 v0.20.0）

> 本段约 395 个 commit，以下为重大更新摘要（已过滤 Bugfix/CI/Docs/Refactor/Test/Build/ROCm/XPU/CPU 等日常维护）。
> 统计：[Bugfix] 74、[CI] 34、[ROCm] 32、[Perf] 11、[Model] 10、[Attention] 6、[Core] 5、[Feature/Feat] 10、[MM] 3、[Kernel] 3、[MoE] 2、[Quantization] 2、[LoRA] 1、[EPLB] 1、[SpecDecoding] 1 等。筛选后得到约 67 条重大更新。

### 本版导读

0.21.0 紧接 0.20.0 的"大换血"之后，是一次"把新架构用到更多模型上"的铺开版本。主题有三条：**MTP 投机解码从 DeepSeek/GLM 系扩展到 Gemma4**（投机解码生态开始多元化）、**MLA 注意力后端完成抽象重构**（为多硬件多后端打地基）、**P/D 分离 + KV 传输生态成型**（Mooncake/NIXL 等连接器就位）。如果你在跟 DeepSeek 系或 MLA 模型的吞吐优化，这版的 MLA 后端重构和双向 KV 传输值得重点关注。

### 头条亮点

1. **Gemma4 MTP 投机解码落地（#41745）**：新增 `vllm/model_executor/models/gemma4_mtp.py`（603 行）与 `vllm/v1/spec_decode/gemma4.py`（335 行），把 MTP（Multi-Token Prediction）作为 proposer 接入 v1 投机解码框架，并扩展 `speculative.py` 配置。这是本版对"用 MTP 部署"最直接的利好——MTP 不再只是 DeepSeek/Glm 系的专属路线，Gemma4 也加入了原生支持。同时 `[SpecDecoding] extend mtp support for mimo 2.5`（#41905）与 MiMo-V2.5 的 MTP 模型（#40967）一起，进一步丰富了 MTP 生态。

2. **TOKENSPEED_MLA 注意力后端（#41778）**：为 Blackwell 平台的 DSR1 / Kimi K25 新增独立 MLA prefill+decode 后端（`tokenspeed_mla.py` 277 行 + prefill 180 行），并配套 attention benchmark 配置。叠加 `[Attention] Abstract the MLA prefill backends and eliminate cuDNN`（#32623，+1629 行重构）——MLA prefill 后端被抽象为可注册的 registry（flash_attn / flashinfer / trtllm_ragged / tokenspeed），彻底移除 cuDNN 依赖。对 DeepSeek 系/MLA 模型的吞吐与可维护性是结构性提升。

3. **P/D 分离 + 双向 KV 传输（#32553）**：新增 `disagg_proxy_multiturn.py`（562 行）与 `test_bidirectional_kv_transfer.py`（915 行），支持 P（prefill）与 D（decode）节点之间**双向** KV cache 传输，prefill 计算可与 KV 传输重叠。配合 `MooncakeStoreConnector`（#40900，+2600 行，Mooncake 分布式 store 做 KV offload）、`MultiConnector SupportsHMA`（#39571）、NIXL connector 升级到 1.x（#42364）与 zero-copy EPLB 传输（#41633），P/D disaggregation 本版显著成熟。

4. **NVFP4 量化全链路打通**：`Add nvfp4 kv cache support`（#40177）让 KV cache 也可用 NVFP4 存储；`ModelOpt NVFP4 W4A16`（#41769）支持 4-bit 权重 + fp16/bf16 激活；`NVFP4 all-gather GEMM fusion for AsyncTP`（#41882）在异步 TP 下融合 all-gather 与 GEMM；外加 Triton NVFP4 dequant/QDQ emulation kernel（#40033）、Blackwell per-token fp8 group quant（#41326）。NVFP4 从权重到 KV cache 到 TP 融合形成闭环，对显存受限场景意义重大。

## vLLM v0.22.0 重大更新（相对 v0.21.0）

> 本版约 474 个 commit，以下为重大更新摘要（已过滤 Bugfix/CI/Docs/Refactor 等日常维护）。仅依据 commit 标题与必要时的 `git show --stat` 改动范围判断，未逐行审阅 diff。

### 本版导读

0.22.0 的关键词是**"投机解码不挑场景"**。前一版 MTP 刚铺开，这版解决的是"能用但不好用"——最关键的是**投机解码与 thinking 模式兼容**了（以前开 MTP 和结构化/thinking 输出会打架），draft 模型也能用独立 attention 后端。对带 thinking 的模型部署，这版是从"会出问题"到"可以放心叠加"的转折点。DSV4 的 MTP 也在更多硬件上铺开。

### 头条亮点

1. **DeepSeek V4 全栈落地**：本版最大主线。新增 DSV4 基础模型支持（含其 MTP，`deepseek_v4.py` / `deepseek_v4_mtp.py`），围绕 Sparse MLA、MHC（multi-head latent）kernel、FP8 稀疏 compressor、Tile Kernels `head_compute_mix_kernel`、TRTLLM gen attention kernel 做了大量性能与重构工作；KV Connector / CPU offload / 前缀缓存（含 sliding-window KV 选择性保留）全面适配 DSV4。这是你用 MTP 部署 GLM-5.2 时最值得对照参考的工程范式。

2. **投机解码与 MTP 持续扩展**：新增 Gemma4 MTP 投机解码（`gemma4_mtp.py` + `v1/spec_decode/gemma4.py`，1121 行新增）、EagleMistral 模型、Cohere Eagle、MiMo 2.5 的 MTP 扩展；支持「带 thinking budget 的投机解码」（reasoning + spec decode 联动，`thinking_budget_state.py` 528 行新增）；允许 drafter 独立选择 attention backend；多模态模型在告警下也可用投机解码。**直接利好 MTP 部署链路。**

3. **KV Cache 二级卸载（Tiered Offloading）体系化**：引入 objectstore 作为二级 KV cache 卸载层，新增 `SecondaryTierManager`、per-request 卸载策略（`on_new_request` 生命周期钩子）、`on_schedule_end()` 步级生命周期分离；HMA 模型默认启用 tiering offload；Mooncake/Nixl connector 大量健壮性与可观测性增强。PD 分离架构进一步成熟。

4. **量化与 MoE 内核全面铺开**：TurboQuant 支持混合模型 + 均匀量化；新增 ModelOpt NVFP4 W4A16、compressed-tensors WNA8O8Int linears、 humming mxfp4 MoE backend；MoE 路由从 routing replay 改为 device cache + 异步 D2H pipeline；W4A8/W4A16/NVFP4/MXFP8 多个 MoE 量化路径迁移到 oracle kernel 架构；LoRA 首次支持 Expert Parallel（EP）+ MoE LoRA one-shot Triton kernel。

## vLLM v0.23.0 重大更新（相对 v0.22.0）

> 本段约 426 个 commit，以下为重大更新摘要（已过滤 Bugfix/CI/Docs/Refactor 等日常维护）。筛选标签：[Feature]/[Feat]/[Perf]/[Core]/[Model]/[Kernel]/[Hardware]/[Attention]/[Quantization]/[MoE]/[MM]/[LoRA]/[EPLB]/[SpecDecode]/[MTP]，并额外纳入 DSV4、MoE Refactor、KV Offload、Rust Frontend 中具有方向性意义的条目。

### 本版导读

0.23.0 是个"埋地基"的版本——表面上没有 0.20 那种大换血的震撼，但做了三件影响深远的事：**KV-Cache 布局大重构启动**（可插拔 KVCacheSpec，为多模型多后端统一内存布局）、**MoE 路由全面迁到 oracle 架构**（量化 MoE 后端选择统一）、**DSA MTP 引入 index share**。这版像是在为 0.24 的"全面成熟"和 0.25 的"换底盘"默默铺路。如果你跟 DeepSeek 系/MLA 模型，KV-Cache 重构和 TOKENSPEED_MLA 后端值得细看。

### 头条亮点

1. **投机解码 / MTP 持续深化，DSA MTP 引入 index share**：`[feature] add index share feature for DSA MTP (#44420)` 给 DeepSeek 架构的 MTP（GLM 同源架构）增加了 index share 能力，改动覆盖 `deepseek_mtp.py` / `deepseek_v2.py` / `llm_base_proposer.py` / `eagle/utils.py`，是本版对 MTP 路径最有感的增强。同期 Gemma4 MTP 进入 Model Runner V2（`#43241`），EagleMistral 新增（`#41024`），Cohere 接入 Eagle（`#42078`），DFlash 支持因果模式并修复 lookahead 块缺失导致的 prefix cache 损坏（`#43445` / `#42971`）。DSA MTP 的 index share 与一组 MTP/Eagle 稳定性修复最值得关注。

2. **KV-Cache Layout 大重构启动 + 可插拔 KVCacheSpec**：`[1/N][KV-Cache Layout Refactor] Refactor DSV4 KV cache config construction (#44454)` 开启了多部分的 KV cache 布局重构（第一篇针对 DSV4 配置构造）；`[KVCache] Support Pluggable KVCacheSpec (#37505)` 让 KV cache 规格可插拔。配合 CPU/AMD/FlexAttention/FlashAttention 统一到「blocks first / num-blocks first」布局（`#44393` / `#43660` / `#42095`），这是本版对 KV cache 子系统最具结构性的改动，影响长上下文与混合模型的内存布局。

3. **MoE 全面迁移到 oracle 后端选择架构**：`[MoE Refactor]` 系列把 WNA16、W4a8-int8、ModelOptMxFp8 等量化 MoE 的后端选择统一迁入 oracle 模块（`#42553` / `#42789` / `#42768` / `#42647`），并移除 `supports_expert_map` 与 inplace fused experts 机制（`#43108` / `#43727`）。同时 Hopper 默认改用 Triton MoE 后端（`#44220`），CUTLASS FP8 scaled mm 旁路 padding 提速 20%（`#43706`），MoE permute 预分配 buffer 提速 9~14%（`#43014`）。EPLB 对 DeepSeek V4 Mega MoE 的支持（`#43339`）与 async EPLB 设为默认（`#43219`）进一步完善了超大 MoE 的专家负载均衡。

4. **DeepSeek V4（DSV4）栈密集打磨 + TOKENSPEED_MLA / TRTLLM kernel**：本版 DSV4 相关 commit 超过 15 条，包括解耦 Sparse MLA 元数据（`#44699`）、refactor DeepseekV4Attention（`#44569`）、 fuse q pad 进 fused kernel（`#43162`）、优化 sparse FP8 compressor kernel（`#44161`）、引入 TRTLLM gen attention kernel（`#43827`）、移除 torch compile 依赖（`#43746`）。外加 `[MLA Attention Backend] Add TOKENSPEED_MLA backend for DSR1/Kimi K25 on Blackwell (#41778)`，对大模型 MLA prefill+decode 在 Blackwell 上的吞吐是实质性提升。

## vLLM v0.25.0 重大更新（相对 v0.24.0）

### 本版导读

0.25.0 是 vLLM 自 2023 年诞生以来**架构转型最彻底的版本**——主题就两个字：**换底盘**。让 vLLM 一战成名的 PagedAttention 原始 CUDA kernel 被彻底删除（约 1472 行），MRv2 成为所有稠密模型唯一默认执行路径。注意：删的是那套老 kernel 实现，"分页管理 KV Cache"的思想没删，由 MRv2 继承。另一条主线是投机解码大爆发（异构词表 TLI、多 drafter）和 Transformers 后端性能追平原生。多数用户无感升级，但引用 PagedAttention 内部 API 或有自定义 attention 后端的需迁移。详见 [FAQ.md](FAQ.md)。

### 头条亮点

1. **PagedAttention 正式退役，MRv2 全面接管推理引擎（架构级里程碑）**
   - 删除 2023 年让 vLLM 一战成名的**原始 PagedAttention CUDA kernel**（commit `d715b3aa1` "Delete PagedAttention (#47361)"，删除约 1472 行：`csrc/libtorch_stable/attention/paged_attention_v1.cu` / `paged_attention_v2.cu` / `attention_kernels.cuh` + `_custom_ops.py` 相关 op）。
   - **MRv2（Model Runner v2）成为所有稠密模型的唯一默认执行路径**，零配置启用。PagedAttention 的分页思想已融入 V1/MRv2 设计，但老的 kernel 代码路径被彻底移除。
   - 这是 vLLM 自 2023 年诞生以来架构转型最彻底的一次：从"单一创新驱动的早期阶段"进入"架构成熟"阶段。迁移注意：若代码/配置引用了 PagedAttention 内部 API 必须移除；大多数用户层 API 无变化，可能感知不到底层换引擎。
   - 伴随能力补齐：动态推测解码兼容完整 CUDA Graphs（此前开推测解码就得关 CUDA Graphs，本版打通）、EVS 支持、Mamba 混合模型前缀缓存、多模态前缀双向注意力。

2. **投机解码大爆发：新增 DSpark、DFlash 多 drafter、MTP for Bailing、异构词表通用 SD**
   - 本版本投机解码（Speculative Decoding）相关 commit 数量显著。NVIDIA 主导的 **DSpark**（DeepSeek-V4 专用 speculator，含非因果稀疏 MLA verifier + SWA）合入主分支并补充 checkpoint 支持；**DFlash** 框架扩展到 Laguna XS.2.1、MiMo（SWA + DFlash）、CPU 平台；**MTP 投机解码首次支持 Bailing 混合（linear attention + MoE）模型**；并实现 **异构词表通用投机解码（TLI, Token-Level Interception）**，让 draft/target 词表不同的模型也能投机解码。

3. **GLM-5 / DeepSeek-V3.2 / V4 一体化高性能实现**
   - 将 DSV3.2/GLM5 纳入 `vllm/models/` 并实现大量算子融合：fused norm+rope+kv-insert、FlashMLA FP8 KV cache（Hopper & Blackwell）、GLM5 Router GEMM、`fused_indexer_q_rope_quant` triton kernel。GLM-5.2 专项优化包括 MoE all-reduce 改 reduce-scatter（+3.1%~3.2%）、FP32 gate、indexer 预热、DSv4 `token_to_req_indices` 缓存带来 5x~6x kernel 提速。DSA（Dynamic Sparse Attention）索引器 + 稀疏 MLA backend 多处打磨。

4. **Attention backend 全面扩展：FA4 (CuTeDSL)、HPC_ATTN 支持 MTP、FLASH_ATTN_MLA_SPARSE、DCP for FP8 KV**
   - 引入 **CuTeDSL warmup 基础设施 + FA4 MLA**（Hopper/Blackwell 新一代 attention）；**HPC_ATTN backend 支持 MTP 与动态调度 attention**；新增 **FLASH_ATTN_MLA_SPARSE** backend（Hopper 稀疏 MLA）；MLA decode 路径支持 **DCP（Dynamic Causal Pooling）+ FP8 KV cache**；FlashInfer MLA 也支持 DCP。

5. **分布式 / 通信 / 可观测性强化：all2all 容错、NCCL 对称内存扩展、DP 优化、可插拔 sleep-mode**
   - 新增 **all2all peer 故障检测 + fault tolerance backend**，防止 MoE all2all 出错时产生损坏输出；**NCCL symmetric memory 扩展到 AllGather 和 ReduceScatter**；DP（数据并行）supervisor 接入 Rust frontend，prefill 节流、load-balancer tie-break 轮转避免引擎偏差；**可插拔 sleep-mode backend 抽象**（RFC #34303）落地；新增 `VLLM_GPU_SYNC_CHECK` 调试环境变量。
