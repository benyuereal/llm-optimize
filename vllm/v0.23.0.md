# vLLM v0.23.0 重大更新（相对 v0.22.0）

> 本段约 426 个 commit，以下为重大更新摘要（已过滤 Bugfix/CI/Docs/Refactor 等日常维护）。筛选标签：[Feature]/[Feat]/[Perf]/[Core]/[Model]/[Kernel]/[Hardware]/[Attention]/[Quantization]/[MoE]/[MM]/[LoRA]/[EPLB]/[SpecDecode]/[MTP]，并额外纳入 DSV4、MoE Refactor、KV Offload、Rust Frontend 中具有方向性意义的条目。

## 本版导读

0.23.0 是个"埋地基"的版本——表面上没有 0.20 那种大换血的震撼，但做了三件影响深远的事：**KV-Cache 布局大重构启动**（可插拔 KVCacheSpec，为多模型多后端统一内存布局）、**MoE 路由全面迁到 oracle 架构**（量化 MoE 后端选择统一）、**DSA MTP 引入 index share**。这版像是在为 0.24 的"全面成熟"和 0.25 的"换底盘"默默铺路。如果你跟 DeepSeek 系/MLA 模型，KV-Cache 重构和 TOKENSPEED_MLA 后端值得细看。

## 头条亮点

1. **投机解码 / MTP 持续深化，DSA MTP 引入 index share**：`[feature] add index share feature for DSA MTP (#44420)` 给 DeepSeek 架构的 MTP（GLM 同源架构）增加了 index share 能力，改动覆盖 `deepseek_mtp.py` / `deepseek_v2.py` / `llm_base_proposer.py` / `eagle/utils.py`，是本版对 MTP 路径最有感的增强。同期 Gemma4 MTP 进入 Model Runner V2（`#43241`），EagleMistral 新增（`#41024`），Cohere 接入 Eagle（`#42078`），DFlash 支持因果模式并修复 lookahead 块缺失导致的 prefix cache 损坏（`#43445` / `#42971`）。DSA MTP 的 index share 与一组 MTP/Eagle 稳定性修复最值得关注。

2. **KV-Cache Layout 大重构启动 + 可插拔 KVCacheSpec**：`[1/N][KV-Cache Layout Refactor] Refactor DSV4 KV cache config construction (#44454)` 开启了多部分的 KV cache 布局重构（第一篇针对 DSV4 配置构造）；`[KVCache] Support Pluggable KVCacheSpec (#37505)` 让 KV cache 规格可插拔。配合 CPU/AMD/FlexAttention/FlashAttention 统一到「blocks first / num-blocks first」布局（`#44393` / `#43660` / `#42095`），这是本版对 KV cache 子系统最具结构性的改动，影响长上下文与混合模型的内存布局。

3. **MoE 全面迁移到 oracle 后端选择架构**：`[MoE Refactor]` 系列把 WNA16、W4a8-int8、ModelOptMxFp8 等量化 MoE 的后端选择统一迁入 oracle 模块（`#42553` / `#42789` / `#42768` / `#42647`），并移除 `supports_expert_map` 与 inplace fused experts 机制（`#43108` / `#43727`）。同时 Hopper 默认改用 Triton MoE 后端（`#44220`），CUTLASS FP8 scaled mm 旁路 padding 提速 20%（`#43706`），MoE permute 预分配 buffer 提速 9~14%（`#43014`）。EPLB 对 DeepSeek V4 Mega MoE 的支持（`#43339`）与 async EPLB 设为默认（`#43219`）进一步完善了超大 MoE 的专家负载均衡。

4. **DeepSeek V4（DSV4）栈密集打磨 + TOKENSPEED_MLA / TRTLLM kernel**：本版 DSV4 相关 commit 超过 15 条，包括解耦 Sparse MLA 元数据（`#44699`）、refactor DeepseekV4Attention（`#44569`）、 fuse q pad 进 fused kernel（`#43162`）、优化 sparse FP8 compressor kernel（`#44161`）、引入 TRTLLM gen attention kernel（`#43827`）、移除 torch compile 依赖（`#43746`）。外加 `[MLA Attention Backend] Add TOKENSPEED_MLA backend for DSR1/Kimi K25 on Blackwell (#41778)`，对大模型 MLA prefill+decode 在 Blackwell 上的吞吐是实质性提升。

## 新特性 [Feature]

- **DSA MTP index share（#44420）**：为 DeepSeek 架构 MTP 增加 index share 特性，触及 `deepseek_mtp.py`、`deepseek_v2.py`、`llm_base_proposer.py` 与 eagle utils，是 MTP 路径的关键增强（与 glm-5.2 MTP 部署直接相关）。
- **DeepSeek V4 Mega MoE 的 EPLB 支持（#43339）**：为 DSV4 Mega MoE 接入专家并行负载均衡，改动 `eplb_utils.py` 与 `deepseek_v4/nvidia/model.py`（约 250 行）。
- **Anthropic Messages API 支持 structured output 与 effort（#42396）**：在 Anthropic 协议层增加结构化输出与推理努力控制。
- **JetBrains Mellum v2 代码生成模型支持（#43992）**：新增 Mellum v2 模型接入。
- **batch invariant RMSNorm with residual（#42453）**：支持带残差的批不变 RMSNorm，利于 CUDA graph 与批一致性。
- **timed trace replay 进 `vllm bench serve`（#39795）**：支持回放 Moonshot / 阿里工作负载 trace 做压测。
- **DP supervisor 的 SSL 支持（#43688）**：数据并行 supervisor 通信支持 SSL。
- **per GPU worker RDMA NIC 选择（#42083）**：可按 worker 选 RDMA 网卡，利于多卡多网卡部署。
- **EagleMistralForCausalLM（#41024）**：新增 Eagle 投机解码版 Mistral 模型。
- **Gemma4 Unified（encoder-free）支持（#44429）**：新增 Gemma4 统一（免编码器）模型。

## 性能优化 [Perf]

- **CUTLASS FP8 scaled mm 旁路 padding，kernel 提速 20%（#43706）**：直接提升 FP8 线性层吞吐，对 FP8 量化模型普遍受益。
- **MoE permute 预分配 buffer，kernel 提速 9~14%（#43014）**：MoE dispatch 路径优化。
- **Hopper 默认使用 Triton MoE 后端（#44220）**：在 Hopper 上把 MoE 默认后端切到 Triton，简化路径并优化性能。
- **Qwen3.5 混合 prefill+decode 批次切分：decode 路由到 recurrent kernel（#44700）**：混合模型把 decode 路由到循环核，提升 SSM/混合架构吞吐（配置含 Qwen3.5-397B-A17B-NVFP4-DEP2-MTP.yaml，与 MTP 相关）。
- **Mamba SSD chunk kernel 增加 do_not_specialize（#43803）**：减少重编译，提升 Mamba 类内核执行效率。
- **KDA 融合 gate softplus / chunk-local cumsum / RCP_LN2 scaling（#43667）**：Mamba/SSM 门控算子融合。
- **H200 / RTX PRO 调优的 selective_state_update 配置（#44251）**：为新一代硬件调优 SSM 状态更新。
- **多模态 item 处理从 O(n) 优化到 O(log n) 每步（#44212）**：长多模态输入下调度开销下降。
- **Triton Top-p 路径单遍 min_larger + 二分查找（#42191）**：采样路径优化。
- **gemma RMS AR 融合（#42646）**：Gemma RMSNorm + 激活融合。
- **CPU→GPU `swap_blocks_batch` 小批量 Triton 快速路径（#42212）**：KV offload 换页路径优化。
- **ROCm wvSplitK skinny GEMM 支持 N=5，面向投机解码（#40687）**：AMD 上为投机解码的瘦 GEMM 增加并行度。
- **DSv4 sparse FP8 compressor kernel 优化（#44161）**：DSV4 压缩器 FP8 内核提速。
- **Fp8BlockScaledMMLinearKernel input_scale 用 new_empty()（#43677）**：减少 FP8 线性层开销。
- **Inductor 自定义算子快速路径回退（#42129）**：`vllm::*/vllm_aiter::*` 自定义算子走 Inductor 快速回退，减少开销。

## 核心改动 [Core]

- **KV-Cache Layout Refactor 启动（#44454，1/N）**：开启 KV cache 布局重构，首篇聚焦 DSV4 KV cache 配置构造。
- **可插拔 KVCacheSpec（#37505）**：支持可插拔 KV cache 规格，为不同模型/后端的 KV 布局提供统一扩展点。
- **KVConnector PP-aware 握手聚合与中间 PP 输出打通（#43720，1/N）**：KV 连接器支持流水线并行感知的握手聚合。
- **KVConnector + PP 清理并修复 MRV2（#43732）**：理顺 KV connector 在流水线并行下的处理。
- **scheduler_block_size 线程化进 KVCacheManager / KVCacheCoordinator（#44165）**：把调度块大小贯通到 KV cache 管理层。
- **max_concurrent_batches 移入 VllmConfig（#44274）**：统一配置并发批次数。
- **worker 模型初始化后冻结 GC（#44363）**：在 worker 中模型初始化后冻结垃圾回收，减少运行期抖动。
- **DP ray placement groups 可绑定到指定节点（#44669）**：数据并行 Placement Group 可指定节点，优化拓扑。
- **稀疏 NCCL 权重传输支持 in-place 更新（#40096）**：前端/核心新增稀疏 NCCL 权重传输，含 RLHF 示例（`examples/rl/rlhf_sparse_nccl.py`），利于在线 RL 权重热更新。
- **统一 reasoning + tool-call 解析到 Parser.parse()（#44267）**：重构，把推理与工具调用解析统一到 `Parser.parse()` 接口（新增 `vllm/parser/abstract_parser.py`）。
- **ResponsesParser 迁移到统一 Parser 接口（#42977）**：解析器统一化的一部分。
- **MRV2 避免流水线并行 bubble（#42187）**：Model Runner V2 减少 PP 气泡。
- **MRV2 为 Llama / Mistral dense 模型启用（#43458）**：MRV2 扩展到主流 dense 模型。
- **MRV2 支持 breakable CUDA graph（#44050）**：可中断 CUDA graph，提升调度灵活性。
- **MRV2 移除 Eagle 专用 CUDA graph pool（#44078）**：简化 Eagle 在 MRV2 下的 graph 管理。
- **MRV2 使用 FlashInfer sampler（#42472）**：采样路径切换到 FlashInfer。
- **MRV2 用实际 batch max_seq_len 构造 attn metadata（#43991）**：修正注意力元数据批次长度。
- **MRV2 为 hybrid + fp8 KVCache 支持新分配块清零（#43990）**：混合模型 + FP8 KV 下清零新块。
- **torch stable ABI 迁移系列（#43361 / #43717 / #44334 / #44365 / #44013 等）**：把 attention、cache、mamba、sampler、all-reduce、DSV4 fused MLA、MXFP8 MoE 等大量自定义算子迁移到 libtorch stable ABI，降低 ABI 依赖与编译耦合。

## 投机解码 & MTP 相关

> 本版对投机解码/MTP 方向投入显著，且多条与 DeepSeek 架构（glm-5.2 同源）直接相关。

- **`[feature] add index share feature for DSA MTP（#44420）`** — 头条。DeepSeek 架构 MTP 增加 index share，改 `deepseek_mtp.py` / `deepseek_v2.py` / `llm_base_proposer.py` / `eagle/utils.py`。对 glm-5.2 MTP 部署最有参考价值。
- **`[Model Runner V2][Spec Decode] Add Gemma4 MTP support（#43241）`** — Gemma4 MTP 进入 MRV2，扩展 MTP 覆盖模型。
- **`[SpecDecoding] extend mtp support for mimo 2.5（#41905）`** — MTP 支持扩展到 MiMo 2.5。
- **`[Spec Decode] Allow causal DFlash（#43445）`** — DFlash 投机解码支持因果模式。
- **`Fix DFlash prefix cache corruption due to missing lookahead block（#42971）`** — 修复 DFlash lookahead 块缺失导致的 prefix cache 损坏（稳定性关键修复）。
- **`[Attention][Spec Decode] Allow independent drafter attention backend selection（#39930）`** — 草稿模型可独立选择注意力后端，利于为 drafter 选更轻量后端。
- **`[Reasoning] Support for speculative decoding with thinking budget（#34668）`** — 投机解码与 thinking budget 兼容，带思考预算的模型也能用投机解码。
- **`[Perf][Spec Decode] Avoid per-step numpy allocation in prepare_next_tokens（#41043）`** — 投机解码每步去掉 numpy 分配，降低开销。
- **`[MRV2][BugFix] Fix KV connector handling in spec decode case（#43719）`** — MRV2 下投机解码的 KV connector 处理修复。
- **`[ROCm][Perf] wvSplitK N=5 面向投机解码（#40687）`** — AMD 上为投机解码优化瘦 GEMM。
- **Eagle 系列**：EagleMistral 新增（`#41024`）、Cohere Eagle（`#42078`）、移除 Eagle 专用 CUDA graph pool（`#44078`）、Eagle3DeepseekV2 `combine_hidden_states` 修复（`#43482`）、EAGLE/MTP lookahead 块缓存进 SWA prefix-cache mask（`#44082`）。
- **MTP/GDN on XPU（#43565）**：XPU 支持 GDN attention 的 MTP。
